# server-lites：LITES 器件级仿真（SpectroLink L2 参考）

> 由总 SKILL 自动调度读取。物理内核复用 spectrolink_core；独立加载、按需启用。**器件库仅内置演示默认（qtf-commercial-decapped），真实音叉参数一律交互获取。**

**版本 v0.1.0**

通过 MCP 协议接入 AI 助手，以自然语言完成 LITES 实验仿真。对全链路逐级建模：激光功率（含调制）→ 器件吸收 + 气体吸收 → 热沉积 → 热波传递（|H_th|∝1/√f 缓变，f_ref=f0/2）→ 热弹应变 → 机械共振 → 压电电荷 → TIA → 锁相 2f → 浓度反演。

## ⚠️ 0. 反直觉前提：LITES ≠ TDLAS

**这是本 Skill 最重要的一条。** LITES 的信号来源与 TDLAS 本质不同，带着 TDLAS 直觉会得出系统性错误的结论：

| 议题 | LITES 实际 | 若套用 TDLAS 直觉会犯的错 |
|------|-----------|--------------------------|
| 信号来源 | **减光口径**：气体把光挖掉（A≈αL），残余光被器件吸收 η_dev → 2f 信号 ∝ η_dev·αL | 以为 α 越大越灵敏、或忽略 η_dev 的量级压制 |
| 灵敏度尺度 | `SBR_gas ≈ (1−e^(−αL)) / am_2f_frac`；**信号绝对值 ∝ η_dev** | 只看 αL，忽略 η_dev 与残余 AM 本底 |
| 标定轴 | **能量积累时间** `τ_acc = Q/(π·f0)` → 要**低** f0、**高** Q | 追求高 f 抑制 1/f → 方向完全相反 |
| 最优 2f | 热波口径 |H_th|=√(f_ref/f)、f_ref=f0/2 ⇒ **最优 f_m≈f0/2**（H_mech 峰处） | 按"热扩散低通压制"误降 f_m → 远离机械共振 |
| MPC 多反射池 | 每反射损失功率 → **信号下降** | 以为光程越长越好 |
| 提高 Q 的收益 | kHz 段 1/f 主导，**不等于**线性改善 LOD | 以为 Q 翻倍 LOD 就翻倍改善 |

> 热波口径下 f_m = f0/2 是理论最优（H_mech 峰、H_th 不衰减）；具体器件的 Q/失谐/噪声折中仍建议用 `lites_sweep` 实测扫描确认。

## ★ 默认器件

不传 `device` 时，所有工具落到 **`qtf-commercial-decapped`**——商用 32.768 kHz 音叉晶振**去壳后的裸音叉**（`f0=32757.4 Hz`、`Q=8630`，常压空气实测，Wang et al. *Opt. Express* **28**(13) 19074 (2020) 表 1）。

**为什么是它**：LITES/QEPAS 领域最通用、最便宜、最可复现的换能器，且 f0/Q 有公开实测锚点。

**但它不是最优**，只是最合理起点。两条必须主动告知用户的局限：

1. **$\tau_{acc}$ 仅 83.9 ms**，而自研低频圆头 QTF 达 361.7 ms（4.3×）。LITES 的正统优化方向是**降 f0**。
2. **噪声口径偏乐观**：叉齿仅 0.33–0.6 mm，与光斑可比，文献实测 1σ 噪声 ~0.3 mV（比大叉齿 QTF 高 ~3×）。本模型**未含**这个几何惩罚 ⇒ 算出的 SNR 偏高、MDL 偏低。要保守估计请把 `sigma_V` 手动放大 3×。

> 用户如果是做 QEPAS 或已有具体器件型号，**应显式传 `device=`**，不要依赖默认值。

### ⚠ 跨器件电压不可比

每个器件的 2f 电压都含一个**私有标定增益 $g$**（由该器件自己的锚点反解，吸收了它自身的 $C_{total}$/$R_{tia}$/`constr`/电极面积等未标定因素）。因此：

- **两个器件的 $V_{2f}$ 比值只反映各自锚点数字的大小，不反映器件优劣。**
- 要比器件本征性能：用 `lites_compare` 的**严格口径**（显式传 `common={'L_gas_cm':X,'power_mW':Y}`，此时才返回 `best_mdl`），或读 $\tau_{acc}$ / $\Theta$ / $H_{th}$ / `SBR_eta` 这类**不含 $g$** 的机理因子。

> 实测自证：单独把 `c_total` 从 20 pF 改到 5 pF，输出变 4.000×；但把 `c_total` 与 `r_tia` **同时**匹配到目标器件后，输出只差 2.2×，与直接对比两器件得到的 27.3× 对不上——因为 $g$ 会随输入重新反解。

## AI 操作规范（必须遵守）

### 1. 交互契约（最高优先级：先读返回值，再谈表达）

每次工具返回里都有三个**机器可读**字段（MCP 层 `_wrap()` 保证它们一定存在）：

```json
"assumptions":        ["……用了默认值/近似的地方……"],
"next_required_actions": ["……你下一步必须做的事（字符串列表）……"],
"disclosure_pending": ["……必须随结论一并向用户说明的事……"],
"interaction":        {}   // 少数工具会填，给出"还能问什么"
```

**执行方式**：

- `next_required_actions` —— **逐条照做**。它们是服务器判定的、本次结果所必需的动作。
- `disclosure_pending` —— **必须覆盖**。里面的每一条都要在同一回答里出现，缺一条就是把结果当成比它更可信的东西报出去了。
- `assumptions` —— 说明哪些参数用了默认值；给定量结论时要标注。
- `interaction` —— 部分工具会给"下一步可以问什么"的建议字段；为空即无建议。

> ⚠️ **诚实声明（勿按设计稿想象）**：本项目**未**实现 `severity` 三级分级
> （`block_conclusion` / `must_disclose` / `advisory`），也**未**实现
> `interaction.conclusion_allowed` / `blocking_reason` 与"同语境不重复下发"的抑制。
> 这些是 `lites_mcp.py` 里 TDLAS 时代留下的**未接线**能力（见 TECHNICAL.md §10.5），
> 当前**不生效**。判断"能否下结论"请直接看工具返回的 `verdict` / `warn_count` /
> `blocking` 类字段本身，而**不要**去读一个不存在的 `conclusion_allowed`。

**两条经实测标定的口径**：

1. **缺参数不阻断结论**。默认工况下 `assumptions` 有几十项（含全部器件参数）。若把"未确认"当阻断，就没有任何一个结果可用了。缺参数走 `disclosure_pending`（披露），阻断只留给"这个数本身不可用"。
2. **不隐藏数据**。结论受限时**不**把定量字段置 `null`——首次调用（必然有默认参数）就拿不到任何数，用户也无法自行复核。改为**数据保留、结论受控**。

### 2. 启动协议

任何 LITES 任务开始前，**先调用 `lites_guide`** 获取交互协议、术语表与保真度台账。台账（`fidelity`）写明"哪些效应已建模 / 哪些未建模"——**未建模项必须随结果披露**。

### 3. 参数澄清（硬约束）

需要澄清时（`clarify.needed=True`）：
- **必须先提问**，获得回答前不得出图或下结论
- 用户明确说"用默认值"时方可跳过
- 提问用结构化选择框，每题 2–4 个固定选项
- 超过 4 题按优先级分批：**器件型号/η_dev → 吸收线/波长 → 调制频率 f_m → 功率/温度 → 噪声口径**

**参数来源优先级**：① 用户实测值 → ② 器件型号（联网检索 datasheet）→ ③ 现场标定 → ④ 默认值并显式标注

**器件型号处理**：用户给出具体型号时，必须联网检索官方 datasheet 提取参数（尤其 **η_dev** 与 **f0 温度系数**），填入仿真并在 `assumptions` 中标注来源。查不到则退回默认值，**不得编造**。

**器件库引用**：已用 `lites_device` 保存过参数时，直接传器件 key，不再逐项索要。

### 4. 结果校验（硬约束）

每次出图或给定量结论前，必须通过 `lites_review` 或返回值里的校验字段。`fail` 时不得下结论，须先修复。

### 5. 出图规范

- 标注技术名称、器件 key、η_dev 取值来源
- 2f 幅值与 1f/本底分离显示（量级差异大）
- 若图上含扫描轴，须说明横轴是**扫描波数**而非瞬时波数
- 落盘路径由 `out_path` 控制；`save_png=False` 则只返回数据

### 5b. `lites_waveform` 面板口径（2026-10 固化）

六子图（3×2 竖版）：
- (a) 音叉电信号 DC 透射包络（真实比例 exp(−αL)，吸收凹陷可见）
- (b) 载波细节（AC 耦合，包络 = R₂f 幅值）
- (c) **正交解调幅值 R₂f = √(X²+Y²)**（与参考相位无关，工程锁相输出幅值；X/Y/X′ 分量保留于返回字段）
- (d) 多浓度 R₂f 谱对比（0–100 ppm 同图，单标度防双重计数）
- (e) 标定曲线（R₂f 峰高 vs 浓度，线性拟合 + 饱和区标注）
- (f) **Allan 方差**（1 Hz × 2 h：白 + 1/f + 漂移；**全整数 τ 网格 1…N/2（1 s 步进）**，τ_opt 精确到 1 s，不做对数抽稀）

### 6. 调制深度 m（易错点）

`mod_depth_cm1` **是真实起作用的参数**（曾因未乘进传递链而被行为审计抓出，现已修复）：

- 峰形因子 `F_raw(m) = m²·exp(1 − m²/2.2²)`，**峰值在 m = 2.2 处等于 4.84**（不是 1）
- 归一化口径为 `F(m) = F_raw(m)/4.84`，使 m 取标定值时 F = 1
- 返回字段：`m`、`F_m`（归一化）、`F_m_raw`、`V_2f_at_m_opt`（换算到最优 m 的电压）
- **不要**把 `mod_depth_cm1` 当成"标定后就无关"的参数——改它会改变输出

### 7. 本底扣除（`use_delta`）

`lites_forward` 同时返回 `V_2f`（含本底）与 `V_2f_delta`（扣除本底）。反演时：
- 有真实零点标定 → `use_delta=True`，并传 `v_2f_baseline_V`
- 只有单点测量 → `use_delta=False`，**必须**说明残余 AM 本底已被包含在结果里
- 不说明用哪种口径 → 反演浓度不可复现

## 关键物理约束（已知坑点）

| 约束 | 说明 |
|------|------|
| η_dev 是全链路最大不确定度 | 它是波长的强函数（LiNbO₃ 在 2.5–4 μm 有声子吸收带 + 2.87 μm OH 基频，3.3 μm 在带肩）。**未实测标定时不要把定量结论说死** |
| 最优 f_m ≈ f0/2（热波口径） | 热波 |H_th|=√(f_ref/f)、f_ref=f0/2 ⇒ 不再"低于 f0/2"；器件具体失谐仍建议 `lites_sweep` 扫描确认 |
| 提高 Q 的收益是次线性的 | 1/f 噪声主导时段，Q 翻倍≠LOD 翻倍改善。看 `lites_noise_budget` 找真瓶颈 |
| MPC 在 LITES 里是负收益 | 多次反射损失功率（信号 ∝ P），259 反射 R=0.98 → 仅 0.5% 吞吐。不要按 TDLAS 惯性推荐长光程池 |
| 温度失谐 | f0 温度系数 −30（石英）/ −80（LiNbO₃）ppm/K。ΔT=1 K 已能造成可测失谐，`lites_resonance` 定量算 |
| τ_acc 是换算量 | `τ_acc = Q/(π·f0)` 由文献结论换算（约 19.7% 量级），**不是独立实测**，勿当作精确值引用 |
| 点值当带误差结果 | 未建模项（自展宽、线混合、PD 暗电流、前放 1/f、Allan 漂移）可能主导真实误差。给定量结论时按台账披露 |
| 反演 σ 必须在目标浓度上求 | 噪声不随吸收信号等比缩放，跨浓度外推可差一个量级 |

## 改动本 server 时的硬规则

| 规则 | 原因 |
|------|------|
| **改工具签名后重跑 `python tools/_gen_schema.py`** | `TOOLS` 是生成产物；手工拼嵌套 dict 括号历史失败 6 次 |
| `_quiet()` **必须**保留 `@contextlib.contextmanager` | 丢装饰器会抛 `AttributeError: __enter__`（已栽过一次） |
| `_SCHEMA_BY_NAME` 由生成器 FOOTER 输出，勿手删 | 曾两次在拼接中丢失 → `tools/call` 抛 `NameError` |
| 改物理后再跑五层验证 | 物理内核 29 / 仪器口径 24 / 服务器 selftest / 保真度审计 / RPC 回归 |
| 路径用 `tools/` 下的相对导入 | Windows 上 `/tmp` 会解析为当前盘根目录，测试脚本写在仓库内 |
